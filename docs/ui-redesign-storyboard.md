# 面试猪产品分镜脚本

## 核心定位

面试猪是一个“实时面试辅助工作台”。它不是聊天软件，也不是配置后台。用户正在面试时，最重要的是：系统持续记录双方对话，自动识别面试官问题，并在中间区域生成可以直接开口说的答案。

新版原型要围绕一个主画面展开：

左边看问题，中间看答案，右边看双方对话和知识命中。

## 分镜主线

### 1. 面试开始前：建立本场上下文

用户新建一场面试项目，选择岗位方向、上传或引用简历、填写 JD，并勾选知识库。

这一幕要让人感觉：答案不是泛泛生成的，而是会结合“我的简历、我的项目、我的知识库”。

画面重点：

- 项目名称和岗位方向
- 简历库选择
- 知识库选择
- 考察重点标签
- 进入面试按钮

### 2. 音频准备：确认豆包 Gateway 识别链路

用户选择会议窗口，开启系统音频，系统显示“Gateway 豆包实时识别”已准备好。

这一幕不需要做得复杂，只要表达清楚两路声音：

- 面试官：系统音频 -> 豆包 Gateway -> 自动触发回答
- 我：麦克风 -> 只记录对话，不触发回答

画面重点：

- 系统音频已连接
- 麦克风记录中
- Gateway 豆包实时
- 进入实时面试

### 3. 实时面试主画面：答案是绝对中心

进入主工作台后，中间是最大的 AI 回答区。面试官说话后，左侧出现识别到的问题，中间开始生成答案，右侧持续记录双方对话。

这是整套原型最重要的一幕。

画面布局：

- 左侧：面试官问题列表，最新问题突出显示。
- 中间：当前问题和 AI 回答，字号更大，像提词稿。
- 右侧：双方对话记录，区分“面试官”和“我”。
- 顶部：听音中、Gateway 豆包、项目名、结束面试。

### 4. 回答改写：快速切换表达策略

AI 回答生成后，用户可以直接点击按钮改写答案。

按钮不要藏起来，要贴着答案区：

- 重新生成
- STAR
- 详细
- 简洁
- 清上下文
- 复制

这一幕要突出：面试中不用重新输入问题，只需要点一下，就能换一种回答方式。

### 5. 结合简历和知识库：让答案有依据

当回答生成时，右侧显示这次答案参考了哪些资料，比如某份简历、某个项目知识库、某组 QA。

这一幕要表达产品的高级感：它不是只会编答案，而是在根据用户自己的材料生成。

画面重点：

- 当前引用简历
- 命中的知识库
- 命中的 QA
- 本场岗位和考察重点

### 6. 面试结束：沉淀记录和复盘

用户结束面试后，系统保留完整的双方对话、所有问答和复盘总结。

复盘不需要抢主流程，但要作为结束后的结果页：

- 本场问题列表
- AI 回答记录
- 优势总结
- 风险点
- 后续追问
- 归档项目

## 主画面一句话

“会议声音在左边变成问题，中间立刻给出可直接说的答案，右边完整记录双方对话，并显示答案参考了我的简历和知识库。”

## 图片原型总提示词

设计一个中文 AI 面试辅助桌面应用，产品名“面试猪”。这是实时面试工作台，不是营销页面。核心画面是三栏布局：左侧是面试官问题流，中间是最大的 AI 回答区，右侧是双方对话记录和知识库命中。系统通过 Gateway 豆包实时识别会议系统音频，记录面试官和我的双方对话；面试官问题自动触发 AI 回答，我的发言只记录。回答区支持重新生成、STAR、详细、简洁、清上下文和复制。答案会结合我的简历、岗位 JD 和知识库。整体视觉专业、安静、低干扰，像一个高质量桌面生产力工具。
