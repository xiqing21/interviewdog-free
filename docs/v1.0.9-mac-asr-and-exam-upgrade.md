## 1. 背景与需求概述

在 `v1.0.8` 发布后，用户在实际面试与笔试辅助的使用过程中，反馈了以下几类核心痛点：
1. **Mac 桌面端 ASR 语音识别不出字**：虽然 macOS 系统音量波形正常跳动（Core Audio 采集正常），但右侧识别列表没有任何文字输出（而 Chrome 网页端正常）；
2. **出现 `@AUTH preflight=0` 提示且识别中断**：用户看到该提示后声音依然无法转写；
3. **识别说完了不自动出答案，一直卡在“识别中”**；
4. **完整句子被异常截断**：如说话“OK，我看你做了两个项目，你可以介绍一下这两个项目”，最终仅剩下“一下这两个项目吗”；
5. **笔试做多道长题目切片混杂**：上一题解答完后，新题目截图被追加到上一题末尾；在笔试大页面（`/exam`）中悬浮窗出现遮挡；
6. **笔试扣费延迟与扣额异常**：做完一道题后时长显示扣减感知不明显。

## 2. 核心技术攻坚与深度排查复盘

### 2.1 Mac 桌面端 ASR 转写不出字（Chromium file:// 保护与 Node.js 代理）
- **现象**：在网页端（`https://mianshizhu.xyz`）麦克风与系统音频 ASR 均正常，但在 Electron 打包客户端中，`mac-audio-helper` 正常产生 PCM 音频块，右侧转写列表没有任何输出。
- **根因分析**：
  - 网页端运行在 `https://mianshizhu.xyz` 下，WebSocket 连接建立时向云端 ASR 网关（`wss://bwg.yihan.me/api/asr-gateway`）发送的 `Origin` 头在服务端的合法白名单内，握手成功并回传 `{"type":"ready","provider":"gateway-doubao"}`；
  - 在 Mac Electron 打包客户端中，前端是通过本地 `file:///.../dist/app.html` 加载的，Chromium 底层发送 `Origin: file://`；
  - **Chromium 网络栈规范严格禁止网页上下文（即使配置了 webRequest 钩子）伪造/重写 WebSocket 的 Origin 请求头**。因此发到服务端的握手直接被网关以关闭码 1005/1008 断开，WebSocket 永远无法进入 `ready` 状态，音频数据在队列中无限堆积。
- **解决方案**：
  - 在 Electron 主进程（Node.js 端，`electron/main.cjs`）引入原生 `ws` 客户端，创建专用 IPC 代理通道：`desktop-asr:connect` / `desktop-asr:send` / `desktop-asr:close`；
  - 在 Node 原生握手时显式注入合法的白名单域名 `Origin: https://mianshizhu.xyz`，彻底绕过 Chromium 内核对 `file://` 的限制；
  - 渲染进程 `src/services/asrGatewayService.ts` 检测到桌面客户端环境时，优先调用 `desktopWindow.asrGateway` 原生桥接。
  - **实测**：握手 200ms 内建立，收到 `ready`，音频流正常进入火山引擎豆包语音识别。

### 2.2 @AUTH preflight=0 权限诊断误判致 ASR 被杀（正则关键字碰撞）
- **现象**：启动听音后，页面偶尔弹出红字报错 `@AUTH preflight=0 (0=authorized 1=denied 2=undetermined)`，同时 ASR 再次停止输出。
- **根因分析**：
  - `mac-audio-helper.swift` 启动时，为便于排查权限状态，会在 stderr 打印系统 TCC 返回值：`@AUTH preflight=0 (0=authorized 1=denied 2=undetermined)`。其中 `preflight=0` 明确代表 `0 = authorized`（**权限完全通过**）；
  - 但主进程 `electron/main.cjs` 监听 stderr 时存在过于宽泛的正则：
    ```javascript
    if (/error|denied|fail/i.test(text)) {
      mainWindow?.webContents.send('desktop-audio:error', text);
    }
    ```
  - **日志说明文字中的 `1=denied` 恰好命中了正则中的 `denied`**！
  - Electron 误将成功的权限诊断日志当作致命音频错误推送给前端，前端触发熔断逻辑调用 `asrGatewayService.stop()`，将刚刚连接好的 ASR 会话瞬间杀死！
- **解决方案**：
  - 在 `main.cjs` 中加入诊断日志白名单：明确跳过以 `@AUTH`、`FORMAT:`、`SUCCESS:` 开头的正常诊断信息，只在真实发生 `Error:` 或 `FATAL:` 时才派发错误事件，杜绝误杀。

### 2.3 语音停顿后不触发答案、卡在“识别中”（静音包死循环重置计时）
- **现象**：说话完毕且过了设定的停顿容忍时间（如 2.5s），依然卡在“识别中”，没有自动触发 AI 答案。
- **根因分析**：
  - 系统音频捕获在说话人停顿后仍在持续运行，每秒向后端推送 10 个静音 PCM 包；
  - 云端网关处理静音包后，每 100ms 都会回传当前已累积转写完整的同一句话；
  - 原前端代码在 `scheduleInterimQuestionCommit` 中，**只要收到回传就无条件调用 `clearTimeout` 重置计时器**！
  - 导致 2.5s 倒计时刚走了 0.1s 就被重置清零，死循环永远无法触发 `commitInterimQuestion()`。
- **解决方案**：
  - **防抖比对**：在 `scheduleInterimQuestionCommit` 中比对规范化文本，若 `normalized === pendingInterimNormalized.current`（说话人已停顿，文字无新增），**绝对不重置定时器**，让倒计时稳定自然跑完；只有在说话人说出新词时才重置续期；
  - 倒计时一到，立即将临时转写转正入库，并自动触发 AI 答案生成。

### 2.4 句子中段被腰斩截断（历史词 indexOf 误截断）
- **现象**：说话为“OK，我看你做了两个项目，你可以介绍一下这两个项目”，最终右侧转写出来的文字被截断为“一下这两个项目吗”。
- **根因分析**：
  - 在 `cleanupInterimText` 中，历史代码为了防止上一句的文字重复出现，遍历了最近提交的历史问题并执行了：
    ```javascript
    const previousIndex = current.indexOf(previous);
    if (previousIndex >= 0) {
      current = current.slice(previousIndex + previous.length).trim();
    }
    ```
  - 用户前一轮对话中包含“自我**介绍**”或“**介绍**”；
  - 当新题目说出“...你可以**介绍**一下这两个项目”时，`current.indexOf("介绍")` 在句子中间（第 17 位）命中，代码将“介绍”及前面所有文字全部砍掉，只剩下了“一下这两个项目吗”！
- **解决方案**：
  - **彻底废除全局 `indexOf` 任意位置切断**；
  - 仅比对最近一条已提交的问题，且**必须满足前缀重叠（`current.startsWith(lastCommitted)`）**时才剥离前缀，句子中间包含相同词汇绝不截断，确保长句 100% 完整保留。

## 3. 笔试辅助系统升级（切片生命周期隔离、路由守卫与商业计费）

### 3.1 跨题目切片生命周期自动重置
- **痛点**：第一题截了多张图拼长图解答后，做第二题时新图追加到了上一题后面。
- **改进**：
  - 在 `ExamContext.tsx` 中增加生命周期状态感知：当上一道题已经生成答案且不在流式中，下一次截屏自动识别为【开启新题】，**自动清空上一题遗留切片与旧答案**，从新题第 1 屏开始；
  - 浮窗底部增加显式【开启下一题 (⌘+⇧+⌫)】重置按钮。

### 3.2 悬浮窗精准路由守卫
- **痛点**：进入大屏版笔试辅助页（`/exam`）时，浮窗依然弹窗覆盖页面。
- **改进**：在 `ExamFastModal.tsx` 中加入精准路由守卫：`if (location.pathname !== '/interview') return null;`，笔试完整大界面中彻底屏蔽悬浮窗，专注独立作答。

### 3.3 笔试 300 秒（5分钟）足额直连扣费与乐观即时感知
- **痛点**：笔试提交解答后扣费感知不明显。
- **根因与改进**：
  - 之前通过云端 API 扣除时，线上旧代码可能存在 `Math.min(60, ...)` 截断；
  - 客户端直接通过 Supabase 执行原子更新：`used_seconds = used_seconds + 300`，足额扣除整整 5 分钟；
  - 前端在开始流式吐出答案的瞬间，乐观即时扣除本地 5 分钟，消除网络与轮询感知延迟。

## 4. 用户体验优化与快捷键体系

1. **移除“等待声音输入...”文本**：
   - 移除顶部浮动提示，静音时保持精致波形指示，检测到声音时实时显示 `系统音量 XX%`（绿色高亮）。
2. **停顿容忍时间恢复为 2.5 秒**：
   - 兼顾自然谈话节奏，防止正常的说话间歇被提前打断。
3. **全流程防切屏全局快捷键**：
   - `⌘ + ⇧ + ↓`（Mac）/ `Ctrl + Shift + ↓`（Win）：向下滚动追加当前屏（拼长图）
   - `⌘ + ⇧ + ↵`（Mac）/ `Ctrl + Shift + ↵`（Win）：提交解答
   - `⌘ + ⇧ + ⌫`（Mac）/ `Ctrl + Shift + ⌫`（Win）：清空当前切片开启下一题
   - `⌘ + ⇧ + A`（Mac）/ `Ctrl + Shift + A`（Win）：暂停 / 恢复自动应答
