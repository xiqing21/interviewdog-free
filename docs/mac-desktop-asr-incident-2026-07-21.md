# Mac 桌面端 ASR、权限与重复 App 排查记录（2026-07-21）

## 用户可见现象

- macOS 的“屏幕录制与系统录音”列表曾出现两项：`MianshiZhu Pro` 与 `MianshiZhu Pro.app`。
- Finder 中同时可见来自 `release` 的 App 与“应用程序”中的 App。
- 从 `release` 打开的版本能识别但明显慢于网页；从“应用程序”打开的版本播放录音没有识别结果。
- 较长语音曾出现只识别到末尾片段、回答因此错误的问题。

## 已确认的文件与安装规则

`release/` 是构建输出目录，不是日常运行目录。它保存 DMG 安装包；打开 DMG 后看到的 `MianshiZhu Pro.app` 是挂载镜像里的临时副本。

日常使用应只保留“应用程序”中的一个副本：

1. 完全退出面试猪。
2. 退出已挂载的 MianshiZhu DMG（Finder 左侧推出）。
3. 从 [v1.0.2-mac Release](https://github.com/xiqing21/interviewdog-free/releases/tag/v1.0.2-mac) 下载 `MianshiZhu-Pro-1.0.2-arm64.dmg`。
4. 打开 DMG，并将其中的 App 复制到“应用程序”；之后只从“应用程序”启动。

2026-07-21 已只读验证 `release/MianshiZhu-Pro-1.0.2-arm64.dmg` 中的 App：版本为 `1.0.2`，Bundle ID 为 `com.mianshizhu.pro`，包含新版 `mac-audio-helper`。仓库中还留有 `1.0.0` / `1.0.1` 的历史 DMG，仅用于追溯，不能作为当前测试对象。

## 两份权限项的根因与修复

历史构建曾改变过 App 名称、Bundle ID / 签名身份，并且曾在应用启动时同时请求“屏幕录制”和“麦克风”。macOS 的 TCC 会把这些历史身份保留在权限界面，因此看起来像有两份授权项。

当前 `1.0.2` 的处理为：

- 固定 Bundle ID：`com.mianshizhu.pro`。
- 未配置 Developer ID 证书时，打包后仍使用固定的 ad-hoc designated requirement，避免每次构建生成新的权限身份。
- 不再启动即请求权限；用户点击“开始听音”后才请求“屏幕录制与系统录音”。
- 桌面端为系统音频模式，不再额外申请麦克风权限。

用户已清理过旧 App 与系统权限后，不应再用历史 DMG 或挂载镜像启动，否则旧身份会再次被 macOS 记录。

## 长语音截断和识别错误的根因

ASR Gateway 约定的输入格式是 **16 kHz、单声道、Int16 PCM**。旧版 macOS ScreenCaptureKit helper 虽然请求 16 kHz / 单声道，但系统可能实际交付 **48 kHz、立体声、浮点或非交错缓冲区**。旧代码直接取第一个原始 buffer 输出，会造成：

- 采样率不匹配，识别端按错误速度解释声音；
- 声道或缓冲区数据丢失；
- 语句较长时出现延迟、截断，甚至只剩末尾词。

`v1.0.2` 已在原生 helper 中显式读取实际音频格式，合并全部声道、持续重采样到 16 kHz 单声道并输出 Int16 PCM；Electron preload 也保持 16-bit 样本边界。源码与 DMG 均已编译、校验。

## “Release 慢、应用程序无声”应如何解释

这两个位置不是两条不同的音频能力：从同一个 `1.0.2` DMG 安装到“应用程序”后，二者的代码应完全一致。出现行为差异意味着测试的不是同一版本或同一权限状态，常见情况是：

1. 直接运行了挂载的旧 DMG（特别是 `1.0.1`），而“应用程序”中是另一版本；
2. “应用程序”中的 App 仍使用旧的屏幕录制 TCC 授权，或启动后没有完全退出并重新打开；
3. 运行的 App 并非 `com.mianshizhu.pro` / `1.0.2`。

因此后续性能判断必须以“应用程序”中的 `1.0.2` 为唯一测试对象，并先在系统设置中确认它有“屏幕录制与系统录音”权限。不要在 `release/` 目录或挂载 DMG 内直接长期运行。

## 尚需真实设备验收的项

构建、DMG、签名身份和音频格式转换已经校验；但实时识别还需要在用户的 Mac 上以当前唯一安装副本播放一段 10–15 秒的语音验收。验收时应记录：

- App 的版本号（必须为 `1.0.2`）；
- 是否显示“系统音频已连接”；
- 从播放开始到首个识别结果的耗时；
- 完整识别文本，以及是否仍只保留末尾片段。

若 `1.0.2` 的唯一“应用程序”副本仍慢于网页，再根据这四项数据检查 Gateway 握手排队、网络往返与服务端上游响应，不应继续通过安装多份 App 进行对比。
